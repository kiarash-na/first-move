# Performance pass · lighter first-load JS

The owner made performance a priority. This pass removes JavaScript from the first load and does not change behaviour or visuals. It does not replace any library and does not rewrite the schema.

## How it was measured

- **Browser** (the owner's script `/tmp/claude-0/js.cjs`): `pnpm build && pnpm start -p 3555`, then Playwright (Chromium) loads each route in a fresh browser and waits for `networkidle`. It sums the gzip size of every `.js` response. The count includes lazy chunks that load after hydration (three.js on the landing) and the prefetches that `<Link>` starts (the landing prefetches the dashboard). The dashboard pages run without a project, so they render the empty state.
- **First load**: every `.js` file in `firstLoadChunkPaths` of `.next/diagnostics/route-bundle-stats.json` (written by `next build`), gzipped. These are the scripts the HTML references, the ones that must load before the page hydrates.
- **Contents**: `next analyze --output --snapshot <name>` and `next analyze export --snapshot <name>` (JSON Lines). The export lists each module's compressed size per output chunk, per route.

On the owner's earlier run `/en` measured 297 k. The 439 k here also counts the dashboard chunks that the landing's links prefetch, because this run waited for network idle.

The Quick Check and Overview pages gain more in the browser measurement than in the first-load table: the chunk that held the MathML went from 76 kB to 52 kB raw. MathML is repetitive, so it compresses very well, and the gzip saving on that chunk is small.

## What changed and why

1. **The landing's three.js scene loads after first paint.** `DistrictScene.tsx` no longer imports `three`. Its effect calls `import('./districtWorld')` after hydration and then mounts the scene. `districtWorld.ts` holds the former effect body unchanged, as `mountDistrictWorld(container, refs, events)`. The SVG fallback shows until the first frame is drawn, as before, so nothing looks different; only the moment three.js downloads moves. A failed import keeps the fallback. New unit test: `DistrictScene.test.tsx`.
2. **The MathML loads when "How we calculate" opens (D-33).**
   - `pnpm gen:reference` now writes two files. `equations.gen.ts` holds the metadata: id, slug, title, file, LaTeX, inputs, tables, flags. `equations-mathml.gen.ts` holds `FORMULA_MATHML`. Before, `map.ts` (`STEP_EXPLAIN`, needed on every step) imported `FORMULA_IDS` and pulled about 30 kB of MathML into the first load. `Formula` no longer has `mathml`/`outputMathml`; they live in `lib/quick-check/explain/mathml.ts`, which is deliberately outside the `@/lib/quick-check` barrel.
   - `HowWeCalculate` (disclosure) and `CalcInfo` (popover) render `LazyCalcExplanation` (`next/dynamic`). Radix mounts the content only while it is open, so the body and the MathML load on first open. Pointing at or focusing the trigger starts the load early (`preloadCalcExplanation`), so the body is usually ready by the click. The loading state is two `Skeleton` bars marked `aria-busy`, with no copy, inside the same bordered panel.
   - `how-we-calculate/index.ts` no longer re-exports `CalcExplanation` and `FormulaMath`.
3. **Example projects load when one is picked (D-04).** The cards already come from the server (`exampleCards`). The client imported `@/lib/examples` (six full projects) only for the click handler, which now uses `await import("@/lib/examples")` after setting `busy`.
4. **The JSON Schema contract is out of the client barrel.** `projectJsonSchema` is no longer re-exported from `@/lib/project`. Agents and tests import `@/lib/project/json-schema` directly, and `index.test.ts` guards this.

## Checked and left as is

- **Zod** (about 34 k gz of a 68 k shared chunk, by the analyzer's per-module estimate) is already tree-shaken: only `zod/v4/core` and `classic` modules are present, and only the `en` locale (1 k), which classic installs by default. `locales/index`, `from-json-schema` and the other locale packs are not in the client. `core/to-json-schema.js` and `json-schema-processors.js` (about 5.5 k) remain, because `zod/v4/classic/schemas.js` imports them statically and attaches a processor to every schema; only `zod/mini` avoids that. Moving to `zod/mini` would save an estimated 7 to 10 k gz and would touch every schema file. Per the brief that is not a large enough win, so it was not done. Validation stays on the client: loading from IndexedDB, `applyPatch`, import and tab sync all need it.
- **lucide-react** is in Next's default `optimizePackageImports` list, and the analyzer shows per-icon modules (`lucide-react/dist/esm/icons/*.js`). **radix-ui**: only the primitives the app uses appear in client chunks, with no unused `@radix-ui/react-*` packages.
- **Recharts** stays lazy (`next/dynamic`, `ssr: false`). It is not in any first load, and `e2e/performance.spec.ts` guards this.
- The rest of the dashboard first load is the Next/React framework (about 133 k, the size of the `/_not-found` first load), the store with its storage modules, the Radix popper/dialog/menu primitives used by the top bar and sidebar, `sonner` (Toaster), and `tailwind-merge`. All of it is needed at hydration.

## Guards

`e2e/performance.spec.ts` gains a test that checks every route's first-load chunks: none may contain `WebGLRenderer`, which now includes the landing, or `<annotation encoding="application/x-tex">`, the MathML marker.
