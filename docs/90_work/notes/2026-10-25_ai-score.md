## Decisions and deviations

- **Decision model and text model** as D-71: Jev takes every decision. The user's text model writes only the report and the suggestions, and the plan text is treated as untrusted data.
- **Label on the stored score.** Method 1.0.0 said "unrounded". The label now reads the score as stored (one decimal), so a saved 70.0 and its label always agree. `METHOD_VERSION` stays 1.0.0 because only scores within 0.05 of a threshold can change. The method file is updated. The display still rounds to 5 (open question 4).
- **Logic placed beside the UI.** The cost estimate (`ai-score/_components/setup/cost.ts`) and the pure result helpers (`results/display.ts`, `anchors.ts`, `labels`, …) sit in the route folder, not in `lib/`, because of the workflow's file ownership (open question 17).
- **ViewSwitch instead of ChartCard** for the results' chart and table switch: the route does not load the `overview` dictionary (open question 15).
- **Examples gained `manualDemand`** (QCT-IN-05, optional), so reference cases can state a known demand. Existing examples are unchanged.
- **Reference-case sourcing.** Building facts come only from `sources.ts`. Invented details are marked "(illustrative)" and proposals "(proposed)". Each fictional case opens with the disclaimer that neither the building's owner nor its operator has planned or endorsed it (D-79). The Seestadt blog was dropped as a source, and with it every claim that rested only on it.
- **Legal pages may link visible docs pages** (`/docs/<slug>`), and **docs pages may link outside the site** only to a URL of the checked reference registry.
- **Provider facts.** ZDR and no-training are stated as *requested*, with Vercel's own plan limits. Transfer bases not verified on an official page stay "under the provider's terms" (open question 7).
- **DE copy** stays a draft under D-44 until O12 removes the marking (D-80).

So a plan at 68 shows 70 and is labelled Promising, and one at 38 shows 40 and is labelled Early. Changing this would move the label thresholds onto the displayed value and needs a `METHOD_VERSION` bump. Keep it as a documented limit? *Decided on 2026-10-25 by the orchestrator on the owner's behalf (D-81, owner to confirm): the label follows the shown score, method 1.1.0 ([follow-ups](2026-10-25_ai-score-followups.md), item 3).*
