## 2. Responsive and accessibility

Checked at 375, 768, 1024 and 1440 px, both themes, EN and DE, by screenshots of every page (contact sheets side by side) plus axe and overflow measurements. The layouts held: no overflow, no clipped content, the sidebar becomes a sheet below 900 px, tables and formulas scroll in named regions. The failures found and fixed:

| # | Finding | Fix |
|---|---|---|
| 1 | axe `label-content-name-mismatch` on every page from 768 px: the language links showed "EN" and "DE" but were named "English" and "Deutsch" (WCAG 2.5.3) | Accessible name is now "EN, English" (`components/language-switch`); tests and the unit tests that looked the link up were adjusted |
| 2 | No way past the sidebar and top bar with the keyboard (WCAG 2.4.1) | `SkipLink` (`_components/skip-link.tsx`, copy `shell.skipToContent`) is the first tab stop; `main` takes focus (`tabIndex=-1`) |
| 3 | The keyboard-focusable chart surface (Recharts `accessibilityLayer`) had its focus ring removed (`outline-hidden` in `components/ui/chart.tsx`) | The ring is back on `:focus-visible` with a 2 px offset; a unit test guards the class |
| 4 | After a project-menu dialog (rename, modules, restore, delete) the focus was lost: the menu item that opened it is gone. With the menu still fading, focus could also stay in the menu while the dialog was open (50 % of runs) | The dialog opens after the menu has closed (`onCloseAutoFocus` of the menu content) and hands focus back to the menu button when it closes |
| 5 | Recharts animates in JavaScript, so the global `prefers-reduced-motion` CSS rule did not stop the bars | `barMotion()` (`dashboard/_components/charts/chart-style.ts`) turns `isAnimationActive` off under reduced motion; all five bar charts use it |
| 6 | Layout shift when the store becomes ready: the top bar moved sideways (project button 44 → 256 px wide, save status 16 → 44 px high), the sidebar's project card grew by 53 px, the Continue card grew by up to 90 px | One project button with a fixed 16 rem width from 1024 px in every state (skeleton while loading), a status skeleton with the final height, a sidebar skeleton with the final height, a taller Continue card minimum. CLS: 0.027 on every project page at 1440 px and 0.073 to 0.081 on the start screen before, **0.000 and 0.014 after** |

Contrast: axe's `color-contrast` rule reports nothing on any page in either theme. The `validate_palette.js` FAILs noted in phase 09 are chart-series brand constraints (see Left).

- **Charts are lazy.** Recharts is one 367 kB chunk that no route lists in its first load; it is requested after the overview paints (tested). The coverage bullet bars are plain SVG.
- **No math library on the client** (D-33): the equations are MathML strings; "katex" in a chunk is only the `class="katex"` of that markup.
- **No layout shift:** CLS 0.000 on every dashboard page at 375 px and on every project page at 1440 px; 0.014 on the start screen at 1440 px (the storage banner appears below the Continue row when the browser denies persistence, which headless Chromium always does).
- **No hydration warnings:** every journey and every page of the CLS test ends with an empty console.
- About 920 kB of the first load is shared by all dashboard routes (React, Next client, zod, Radix, the project engine and the equation text). The budget test in `performance.spec.ts` fails above 1150 kB uncompressed for the overview.

## Deviations and documented defaults

1. **A light-theme run is one of three journey tests**, not a separate file. The light theme is set through the theme button, as a user does.
2. **Export and delete are driven through the real UI**; import uses the start screen's file input (`setInputFiles`), since a native file chooser cannot be scripted.
3. **The a11y and responsive suites live in e2e**, so they run on the production build; they take about 2.5 minutes together with the rest (2 workers).
4. **Plan step 5 asks for a list of what is left; it is below.**
5. **Commit trailer.** The task text names a model in the `Co-Authored-By` line; the session's attribution reminder names another and wins (same as phase 09). The commit uses the reminder's lines.

Smaller follow-ups found along the way:

- **Status code for unlisted params.** `notFound()` for a param outside `generateStaticParams` (an unknown step or docs slug) returns 200 on the first request and 404 afterwards (phase 01 follow-up). The UI and `noindex` are always right, so the e2e tests assert those. Revisit if a crawler matters; there is no Next.js option for it yet.
- **"Recently deleted" list.** `listDeleted` exists in the store but the UI does not show it; delete has confirm plus undo, and a "before-delete" snapshot (restore from the project menu).
- **Chart contrast in light mode.** If the owner wants stricter series contrast, raise the mix share of `--chart-3` / `--chart-4` in `app/globals.css` (phase 09 note).
- **Sticky share-sum bar** on the buildings step overlaps the last grid rows while scrolling (by design); revisit if testers find it in the way.
- **Pitch readiness** is the team's reading of the pitch sections and jury criteria (D-30, phase 10): change `ROW_REQUIRED` in `lib/business-plan/` if the owner wants it stricter.
- **Real-device check.** Everything here ran in headless Chromium. A pass on Safari and Firefox, and on a phone with a screen reader, is still worth doing before a public demo.
