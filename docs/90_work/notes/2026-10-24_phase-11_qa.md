## Deviations and documented defaults

1. **A light-theme run is one of three journey tests**, not a separate file. The light theme is set through the theme button, as a user does.
2. **Export and delete are driven through the real UI**; import uses the start screen's file input (`setInputFiles`), since a native file chooser cannot be scripted.
3. **The a11y and responsive suites live in e2e**, so they run on the production build; they take about 2.5 minutes together with the rest (2 workers).
4. **Plan step 5 asks for a list of what is left; it is below.**
5. **Commit trailer.** The task text names a model in the `Co-Authored-By` line; the session's attribution reminder names another and wins (same as phase 09). The commit uses the reminder's lines.

## Final review fixes

Three independent final reviews reported ten findings. Each was reproduced first (Playwright on the production build, or a unit test that failed before the change). All ten were real and are fixed. Nothing was rejected and nothing needed an owner decision. Findings 3 and 7 are the same defect.

| # | Finding | Outcome |
|---|---|---|
| 1 | **Clear all shares** (Buildings step) wiped the 5×5 grid in one click, with no confirmation and no undo (D-02) | **Fixed.** `ClearSharesDialog` (`_steps/buildings/clear-shares-dialog.tsx`, the same AlertDialog pattern as `RemoveRowDialog`) asks first. The copy is `quick-check.ui.buildings.confirmClear` (EN only, D-32). Covered by unit tests and the e2e `review-fixes.spec.ts` |
| 2 | Classified values were rounded for display but classified on the exact value, so a value just under a band edge was shown across it (`100%` next to "Conditionally feasible" at 99.76 %; E 0.996 → `1`; heat density 0.496 → `0.5`) | **Fixed.** `roundWithinClass` / `indicatorDisplayValue` (`lib/quick-check/classify/display-value.ts`) round normally unless that lands in another TBL-7..10 / OQ-21 band. In that case the value is cut toward its own class: 99.76 % → `99%`, and 30.04 buildings/ha → `30.1` because "Above 30" is exclusive. `formatIndicator` (`lib/dashboard/indicator-format.ts`) applies this to coverage, building density, heat density, CH ratio and E on the results cards, indicator grid, result rail, overview KPIs, tiles, coverage chart and the area preview. The class still comes from the exact value; no methodology changed. The reviewer's case (demand 413,500 kWh/a) now shows `99% · Conditionally feasible` |
| 3, 7 | `formatEur(…, { compact: true })` showed tenths of a euro in DE, because German has no compact form below one million: `89.577,5 €`, `631.083,3 €`, `8712 €` | **Fixed.** Compact output keeps one fraction digit only when the language actually abbreviates the amount (the `compact` part of `formatToParts`). Otherwise the amount is formatted as whole euros in standard notation: `89.578 €`, `631.083 €`, `8.712 €`. EN is unchanged (`€128.1K`). DE unit tests were added |
| 4 | Every keystroke is patched, so a number that ends up out of range left its typed prefix in the project. Tests: the hook (`100001` key by key leaves the stored value as it was), `NumberField`, the share grid, and an e2e test that checks the area preview and the stored value after navigating away and reloading. This deviates from the phase-08 note, which said the project keeps its last valid keystroke |
| 5 | The sticky share-sum bar covered focused share cells (WCAG 2.2 2.4.11): 16 of 25 at 375 × 740 and 5 of 25 at 1440 × 900 | **Fixed.** Share-grid inputs have `scroll-margin-bottom: 11rem`, so focus scrolling stops above the bar.
